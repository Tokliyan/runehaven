## Secondary discrepancy (would need a decision even if v16 existed)

The spec says Enchanted Forest and Sacred Meadow should follow

> "the exact same pattern already used for Dark Forest (a rarer pocket embedded
> within an existing biome via **the hashed-patch technique** already in the
> world-build code — search for how Dark Forest is generated and mirror that
> approach, do not invent a new worldgen method)"

Dark Forest is **not** generated by a hashed patch. It is a moisture-fBm
threshold band inside the land elevation range — `runehaven.html:629`:

```js
const m = fbm(tx + 999, ty + 999, worldSeed + 31);
...
if (m > 0.70) b = B.DARKFOREST;
else if (m > 0.52) b = B.FOREST;
else if (m < 0.32) b = B.MEADOW;
else b = B.PLAINS;
```

So "match the existing constant" is also underdetermined: the existing constant
`0.70` is a threshold on a *continuous moisture field shared with Forest and
Meadow*, not a per-tile `hash2` rarity roll. Mirroring the real technique
(pushing the moisture band further, e.g. a `m > 0.8x` pocket) carves Enchanted
Forest out of Dark Forest, not out of Forest as the spec requires; getting a
pocket *within Forest tiles* specifically needs a second independent field,
which is a different technique from Dark Forest's. This is resolvable but needs
an explicit call, so flagging rather than guessing.
